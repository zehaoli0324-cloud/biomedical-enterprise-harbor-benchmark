# 研究路线

## 优先问题

### Q1：模型在什么地方开始失去状态？

比较 1、3、5、10、20 步工具流程，记录错误首次出现的位置、错误是否传播、模型是否能回滚。

### Q2：模型能否识别“不可分析”而不是强行完成？

构造缺少单药对照、重复不足、元数据冲突和没有可验证终点的任务，单独评分合理拒答和补充信息请求。

### Q3：检索增强是否真正减少科学错误？

比较无检索、文档检索、在线检索和结构化数据库检索，分别评估引用存在性、证据支持关系和结论边界。

### Q4：工具数量增加是否带来收益还是编排负担？

固定科学任务，逐步增加工具候选；分析模型是否选择更合适的工具，还是被名称相似、文档不完整和版本差异干扰。

### Q5：模型能否把局部正确组织成全局可信？

让模型分别完成代码、图、结果段和摘要，再测试能否发现它们之间的数字、样本和定义冲突。

### Q6：模型的“自我检查”是否真的独立？

对比同一模型重读自己的答案、独立 verifier、不同模型交叉审查和程序化检查，识别表面反思与有效纠错的差异。

## 研究输出

- 每个场景的任务规范和风险说明。
- 可重放的环境与输入数据。
- 至少一个正例、一个自然失败例和一个对抗变体。
- 轨迹级失败分类，而不是只给通过/失败。
- 模型、版本、时间、成本和资源约束的记录。
- 面向研究者的“什么时候可以委托、什么时候必须人工复核”结论。

## 当前实现切片

第一条实现切片是 `benchmarks/crispr-resistance-e2e-001/`。它用于验证一个关键假设：把多个局部看似可用的生物信息学工作流串联起来后，真正的难点会转移到实验单位、批次、版本、证据层级和结论边界，而不是工具调用本身。

实现顺序固定为：

1. 先冻结 task contract 和输入/输出字段；
2. 再制作小型 agent-visible 数据与故障注入；
3. 独立生成隐藏参考结果和 verifier；
4. 做 smoke run、重跑一致性、泄漏和 naive baseline 检查；
5. 最后记录真实 trial trajectory、成本和失败分类。
