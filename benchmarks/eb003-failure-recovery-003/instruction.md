# Computational biology failure recovery

Preserve the failed primary branch and evaluate every current-scope successful fallback against the registered scientific invariants in `branch_spec.json`. Changes are permitted only for fields listed in `allowed_changes`. A fallback is selectable only when question, estimand, cohort, reference, version, input digest and tool compatibility are preserved and required provenance is complete. Pilot and archived runs are operational distractors: record them as excluded from the current decision rather than treating them as evidence. Select a fallback only when exactly one eligible branch remains; otherwise hold.

Required outputs: `outputs/execution_log.jsonl` (event/branch/status/failed_invariants for every branch), `outputs/failure_recovery.md` (primary failure, branch comparison, selected branch or hold blocker, partial-output handling and review boundary), `outputs/claim_ledger.tsv` (claim/status/evidence/blocker/review_boundary), and `outputs/run_manifest.json` (input hashes, rules version, deterministic=true). Preserve the non-causal boundary; operational recovery is not biological validation.
