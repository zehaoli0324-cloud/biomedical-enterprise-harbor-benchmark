# Agent 任务说明

你是负责功能基因组学分析的计算生物学家。你的目标不是生成一份看起来完整的报告，而是判断一个候选基因是否值得进入药物耐药机制的单基因验证。

你将获得一个工作目录，其中包含 pooled CRISPR screen、bulk RNA-seq、amplicon 测序、文献材料和约束文件。请先检查输入契约和资源预算，再决定哪些分支可以分析。所有工具版本、参数、输入 checksum、失败和降级决策都必须记录。

## 科学问题

在给定的人源肿瘤细胞药物处理实验中，寻找同时满足以下条件的候选靶点：

- pooled screen 中有方向稳定、重复可解释的信号；
- bulk RNA-seq 对应比较和通路结果支持一个合理机制；
- 文献证据能支持具体主张，而不是只有关键词相关；
- 至少有一个满足 PAM、位点和脱靶约束的 guide；
- amplicon 测序的编辑结果质量足以支持后续实验决策。

不要把这些条件合并成一个没有解释的总分。分别报告观察、统计结果、机制解释、行动建议和仍需验证的内容。

## 必须遵守的顺序

1. 先读取 `data/constraints.yaml`、样本表、参考版本和文件 checksum。
2. 建立变量字典，声明实验单位、对照、批次、比较方向和排除规则。
3. 运行或复核 screen 与 RNA-seq 的 QC；发现不可分析输入时先记录并暂停对应分支。
4. 只有在统计设计明确后，才生成候选基因排序。
5. 对候选基因执行 guide 设计和脱靶审查；模型分数不能替代风险判断。
6. 用 CRISPResso2 或等价的固定配置分析编辑结果，并报告可用 reads 和 QC。
7. 建立证据表和 `claim_ledger.tsv`，让每个关键结论都能定位到具体来源或中间产物。
8. 生成图表和最终报告，并逐项检查正文、图、表和日志中的数字是否一致。

## 禁止的捷径

- 不得把细胞数、reads 数或 sgRNA 数当成生物重复数。
- 不得用组合/处理组对照差异替代 screen 的正确富集模型或交互问题。
- 不得把 guide score、预测结构或模型置信度写成实验确认。
- 不得把相关性、共表达或文献摘要改写成因果结论。
- 不得静默修复样本标签、参考版本或单位冲突。
- 不得在缺少可用数据时编造数字、引用、编辑率或工具输出。

## 交付

请将所有规定文件写入 `outputs/`，并至少包含：

- `study_plan.yaml`
- `evidence_table.tsv`
- `screen_results.tsv`
- `rna_mechanism.tsv`
- `target_ranking.tsv`
- `guide_candidates.tsv`
- `editing_validation.tsv`
- `claim_ledger.tsv`
- `workflow_bundle/`
- `final_report.md`

`final_report.md` 的最后一节必须是“结论边界与下一步实验”，并明确说明当前证据是否足以支持因果性结论。若任务因输入冲突无法完成，应提交已完成的中间产物、失败日志、最小补充信息请求和降级结论，而不是填充一个确定答案。
